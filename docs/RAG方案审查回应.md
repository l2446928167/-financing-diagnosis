## 二、必改项评估

### 1. 分块策略（条/款切块 + 两层结构）
- **判定：采纳**
- **对现有索引结构的改动量（中等）**：现行方案是 `corpus.jsonl`（文档级）+ `bm25_index.pkl`。改为**两层**：`docs.jsonl`（文档元数据：id/title/source/url/date/category）+ `chunks.jsonl`（chunk_text / doc_id / clause_no / header）。索引在 chunks 上建，检索返回 chunk，通过 `doc_id` 回指文档。
- **引用粒度提升效果（大）**：从"依据《XX办法》"升级为"依据《XX办法》第X条"，对 to-G / to-B 场景的可信度是质变——评审/监管最吃"条款级出处"。
- **调整点**：条/款切分**仅用于政策类**（用正则匹配 `第[一二三…]+条` / `(一)(二)`）；products / research 本就短，保持单 chunk。chunk 头部拼"标题+条款号"是纯文本拼接，不影响 bi-gram 分词。

### 2. 语料采集降级链
- **判定：采纳**
- **执行顺序合理性（好）**：`产品文档优先转换 → 政策走降级链 → 研报摘要`。产品来自本地 `products.csv`，零网络依赖，能**立刻打通 分词→建索引→检索→渲染**全链路做冒烟，把"外部抓取不确定性"隔离到最后。
- **风险控制效果（好）**：每篇标注实际层级（`full_text` / `extracted_body` / `pdf_text` / `abstract`），报告可如实披露来源质量；末级（摘要+url）仍能溯源到原文，不编造。
- **补充**：PDF 文本提取无需新增依赖——项目已用 `pdfplumber` 解析财报，复用即可。

## 三、建议项评估

### 3. 数字串保留 + 中文 bi-gram
- **采纳**。分词器改为：连续 `[0-9a-zA-Z.%]+` 保留为完整 token，其余中文走 bi-gram。金融场景 `"利率4.35%"`、`"LPR"`、`"信用贷"` 的精确匹配直接决定产品推荐命中率，改动 <5 行。

### 4. BM25 自实现 vs rank_bm25
- **采纳（调整原计划）**。原方案把 rank_bm25 列为依赖、自实现仅作兜底；现改为**直接自实现 Okapi BM25（~40 行，纯 stdlib）**，从 `requirements.txt` 删掉 rank_bm25。理由：零新增依赖 = 彻底消除 Py3.14 wheel 不确定性，且 40 行实现可读可测，无编译风险。注意 IDF 平滑与文档长度归一化别写错。

### 5. grounded_answer 调用参数
- **采纳**。`temperature=0` 保证事实生成可复现；回答内用 `[1][2]` 编号引用，末尾附**参考清单**（title/source/url/date），与 `report_generator` 的"政策与产品依据"小节同构，引用可机器校验。

### 6. 事实性修正
- **采纳（必须）**。2023 年银保监会改组为国家金融监督管理总局，域名 `cbirc.gov.cn` → **`nfra.gov.cn`**；银税互动主管为国家税务总局 **`chinatax.gov.cn`**。原方案列的 `cbirc.gov.cn` 是死域，评委查链接必穿。同步确认 `pbc.gov.cn`（央行）、`gov.cn`（国务院令）、`samr.gov.cn` 仍有效。

### 7. 冒烟测试升级回归集
- **采纳**。固定 6–8 组查询 + 期望 top-5 `doc_id`，每次重建索引后断言 `recall@5 ≥ 阈值`。因 BM25 自实现 + 分词器改动，回归集是防回退的刚需。用例如："科技型小微无抵押能贷多少"→产品、"小微授信监管评价看什么"→政策、"征信不良能贷吗"→政策。

### 8. 无 API Key 降级
- **采纳**。`grounded_answer` 检测 LLM 不可用（无 key / 超时）时，回退为"返回 top-k chunk 原文片段 + 来源"，功能不崩、检索价值仍可见，适合离线演示与答辩断网兜底。

### 9. 语料新鲜度校验
- **采纳（低费）**。build 时记录 `products.csv` 哈希，不一致则告警（防有人改产品表后索引静默漂移）。可顺带记录各政策 url 的抓取日期；404 检测作为可选增强。

### 10. top-k 去重
- **调整**。**采纳 doc_id 去重**（同文档多 chunk 入榜时仅留最高分，每 doc 至多 2 chunk，保多样性）；**暂缓模糊"相似度>80%"**——相似度需额外计算且易误并不同条款，收益低、风险高。用 doc_id 去重已解决 90% 重复问题。

### 11. mock LLM 测试
- **采纳**。`scripts/smoke_rag.py` 用 mock LLM（返回引用检索 chunk 的罐头答案）跑通 prompt 拼装 + 引用格式化 + 解析，不耗 key、可进 CI。

### 12. reportlab 长 URL 溢出
- **采纳**。报告"依据"小节只显示**来源机构 + 检索日期**（URL 截断为域名或省略），规避长 URL 撑破 PDF 版式。RAG 接入报告时一并处理。

### 13. 内存验收方法
- **采纳（放验收期）**。索引 load 前后读 `RSS`（`resource.RU_MAXRSS` 或 `/proc/self/statm`，纯 stdlib，不引 psutil），差值写入验收记录，门禁 <50MB，作为"不上 OOM"的硬证据。本任务构建阶段不阻塞，部署前验收。

### 14. app.py 冻结纪律
- **采纳**。RAG 全部收敛进 `utils/vector_store.py`（自包含）+ `scripts/build_rag_index.py` + `scripts/smoke_rag.py`，`app.py` 接线统一留到"接线阶段"——与本任务"只新增文件、不改现有文件"纪律完全一致，避免与并行开发冲突。

## 四、修订后执行优先级清单

**P0 — 地基（零外部依赖，先打通不依赖网络）**
1. 自实现 `BM25Okapi`（纯 stdlib）+ 自定义分词器（数字串保留 + 中文 bi-gram）；**删 rank_bm25 依赖**。
2. 两层语料结构：`docs.jsonl` + `chunks.jsonl`；政策按条/款切、头部拼"标题+条款号"，products/research 单 chunk。
3. **产品文档优先**：`products.csv` → 20 篇 product doc，立刻本地冒烟全链路。

**P1 — 核心功能（采集 + 检索 + 生成）**
4. 采集降级链：政策走 全文→抽取→PDF→摘要+url，每篇标层级；顺序 products→政策→研报；**域名白名单修正**（nfra / chinatax / pbc / gov / samr）。
5. `grounded_answer`：`temperature=0` + `[n]` 编号引用 + 参考清单；**无 Key 降级**纯检索。
6. 回归集 6–8 例 + `recall@5` 校验；`products.csv` 哈希新鲜度校验。

**P2 — 打磨 / 验收**
7. top-k 按 `doc_id` 去重（每 doc≤2 chunk）；**暂缓**模糊 80% 相似去重。
8. `scripts/smoke_rag.py` 接 **mock LLM**，离线跑通 pipeline。
9. `report_generator` 接 RAG 依据小节：只显来源机构+检索日期（长 URL 截断），防溢出。
10. **内存验收**：load 前后 RSS 差值 <50MB，写验收记录。
11. `app.py` 接线统一留到最后阶段（冻结纪律）；本任务只交付自包含模块 + 独立冒烟脚本。
