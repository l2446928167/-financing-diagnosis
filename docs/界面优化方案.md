# 界面优化方案：AI + 小微企业融资诊断系统（v1.6 → v2.0）

**对象**：`l2446928167/-financing-diagnosis`（Streamlit 单页应用，最新提交 v1.6 统一接线版）
**依据**：app.py / modules/diagnosis.py / README / .streamlit（无 config.toml）源码逐一核对
**参考风格**：Linear / Notion（克制留白、细边框卡片、单一主色）、Stripe Dashboard / Mercury（金融 B 端语义色纪律）、Ant Design Pro（中文 B 端布局范式）

---

## 一、现状盘点

**技术事实**：
- 单文件单页 `app.py`（约 600 行 UI），无 `.streamlit/config.toml`、无一行自定义 CSS → 纯默认主题。
- 页面自上而下约 **10 个区块**：侧边栏配置 → 文件上传 → 指标修正墙（动态 N 个 text_input，3 列）→ 会计校验 → AI 提取 → 原始数据 expander → 补充经营信息（2+3+3+3+2 共 5 组控件）→ 诊断按钮 → 诊断结果（总评分 + 8 维 2×4 指标卡）→ 双轨对照（ML 概率 + 结论 + SHAP expander）→ 风险/建议 → 产品匹配表 + AI 推荐 → 差距分析（行动表 + 逐产品 expander）→ 报告下载 → **产品库全表常驻** → RAG 问答区。
- 红黄绿灯是 `diagnosis.py` 返回的纯文本 `"🟢 绿色"`，用 `st.markdown` 贴在 metric 下方。
- 8 维评分用 2 行 × 4 列 `st.metric`；SHAP 用默认 `st.bar_chart`；所有表格为默认 `st.dataframe`。

## 二、问题清单（按严重度）

### P0：交互缺陷（比"不美观"更严重，演示事故高发区）

**P0-1 结果区生命周期 bug —— 一次提问，全页结果消失**
`app.py` 中诊断结果、产品匹配、差距分析、报告下载**全部渲染在 `if st.button("🔍 开始金融健康诊断"):` 块内**。Streamlit 中按钮只在点击当次 rerun 返回 True；之后**任何**控件交互（改指标、保存 Key、在页面底部的 RAG 区提问）都会触发 rerun，按钮回到 False → 上方所有结果瞬间清空。`diagnosis_result` 虽存进 session_state，却从未被重渲染。而 RAG 问答区恰好位于结果区**下方**，用户诊断完往下滚动提问 → 结果全没。这在评委演示时是致命场景。

**P0-2 无 st.form / st.fragment，逐键全量 rerun**
录入区 15+ 个控件每个变动都整页重跑。224 页年报（21.6 万字符）的 `raw_text` 常驻 session_state，每次 rerun 重新执行指标墙重建等逻辑，在 1GB 内存的 Community Cloud 上是实打实的卡顿/OOM 风险。

### P1：信息架构（"页面过于复杂"的根因）

- **P1-3 单页信息过载**：录入 → 诊断 → 双轨 → 建议 → 匹配 → 差距 → 报告 → 产品库 → 问答，一条长滚动到底，无导航、无分区锚点。
- **P1-4 指标修正墙**：动态数量的 `st.text_input` 三列平铺，单位/来源页缩成 caption 小字，既难扫读也无法做数值校验。
- **P1-5 常驻冗余**：产品库全表（19 列 × 20 行）永远占据底部；补充信息 5 个子区块平铺，"行业周期信号"这类演示用高级项与必填项混在一起。
- **P1-6 无法纯手动演示**：补充信息区在 `if uploaded_file` 内，不上传文件连诊断按钮都不出现——评委现场想手填几个数演示都不行。

### P2：视觉表现

- **P2-7 无视觉系统**：默认主题、无 page_icon、无品牌主色、无卡片/徽章样式。
- **P2-8 emoji 过载、层级混乱**：15+ 个 emoji 标题（🏦📤🔍🧠📊💡📄📋📚🤖⚙️💾🔌🔑📈），`st.header`/`st.subheader` 混用无规律。
- **P2-9 数据可视化弱**：8 维评分是 2×4 的 metric+文字灯，信息密度低且不直观；SHAP 默认条形图无正负配色；匹配表格无列格式化（匹配度/状态应是进度条与徽章）。
- **P2-10 细节失分**：侧边栏明文回显 API Key 前 6 后 4 位（安全隐患且显脏）；模型下拉只有 1 个选项（纯噪音）；空状态只有一行 `st.info`。

## 三、优化方案

### 3.1 整体视觉风格（Design Tokens）

定位：**「克制、专业、可信」的金融 B 端**。少即是多——评委注意力应留给双轨对照和 SHAP 这些"AI 含金量"内容。

| Token | 值 | 用途 |
|---|---|---|
| 主色 | `#1F4E79`（金融深青蓝） | 按钮、链接、Tab 选中态、标题强调 |
| 语义色 | 绿 `#16A34A` / 黄 `#D97706` / 红 `#DC2626` | 仅用于红黄绿灯与双轨结论徽章，不作装饰 |
| 中性色 | `#F7F8FA` 页面底 / `#FFFFFF` 卡片 / `#E5E7EB` 细边框 / `#374151` 正文 / `#6B7280` 次要 | 全部背景与文字 |
| 圆角/间距 | 卡片 12px、控件 8px；8pt 间距系统 | 全站统一 |
| 字体 | 系统栈（思源黑体/苹方/Segoe UI） | 中文 B 端最稳妥 |

落地方式（两段代码即可，见第五节）：`.streamlit/config.toml` 设主色与背景 + 一段 `st.markdown(..., unsafe_allow_html=True)` 注入卡片/徽章/hero CSS。

emoji 纪律：全站只保留 3 处功能图标（上传、开始诊断、下载报告），其余标题去 emoji 用文字层级表达。

### 3.2 页面布局简化（信息架构重构）

单页 → **`st.tabs` 四标签页**（单文件即可实现，不必上 `st.navigation` 多页架构，改动最小）：

```
Tab 1 数据录入      Tab 2 诊断报告        Tab 3 产品匹配        Tab 4 政策问答
─────────────      ─────────────        ─────────────        ─────────────
上传区(空状态hero)   总览条：大数字评分     匹配表(列格式化)      居中搜索框
指标确认(编辑器表)   +红黄绿徽章+双轨结论    AI推荐卡片            结果卡片
补充信息(st.form)   8维横向条形图(色带)     行动优先级表          引用清单(chips)
sticky 诊断按钮     风险/建议两列          差距expander          语料范围切换
                   SHAP归因expander      产品库折叠到底部       meta信息一行
                   报告下载卡
```

要点：
- **产品库全表**移入 Tab 3 底部 `st.expander("查看完整产品库")`。
- **补充信息**分两组：必填基础组（经营年限/行业/利率/客户集中度）+ `st.expander("高级选项（信用记录 / 行业周期信号等演示参数）")`。
- Tab 1 顶部做空状态 hero：一句话价值主张 + 三步流程图（上传 → 确认指标 → 开始诊断），替代孤零零一行 info。
- 诊断按钮在每个相关 Tab 都能到达：结果渲染到 session_state 后，Tab 2/3 直接可读（见 3.3 P0 修法）。

### 3.3 交互体验改进

1. **修 P0-1（结果持久化）**：诊断计算仍在按钮块内执行，但**渲染全部移到块外、从 session_state 读取**：
   ```python
   if st.button("开始金融健康诊断", type="primary"):
       st.session_state.diagnosis_result = diagnose(full_metrics)
       st.session_state.full_metrics = full_metrics   # 供匹配/差距/报告复用
   if st.session_state.diagnosis_result:              # 块外渲染，rerun 不丢
       render_diagnosis(st.session_state.diagnosis_result)
   ```
2. **修 P0-2（表单化）**：录入区全部控件包进 `st.form` + `st.form_submit_button`，一次提交一次 rerun；RAG 问答区包 `st.fragment`，检索只局部刷新。
3. **指标墙 → `st.data_editor`**：一张表（指标｜数值｜单位｜来源页），数值列用 `NumberColumn` 带校验，来源页只读灰显；比 3 列 text_input 节省约 60% 纵向空间。
4. **表格列格式化**：匹配度用 `ProgressColumn`，匹配状态用带色徽章文本列；行动优先级表冻结首列。
5. **8 维评分升级**：横向条形图，条长按分数、条色按红黄绿阈值（`altair` 一行 `condition` 即可，streamlit 自带），比 2×4 metric 密度高一倍。
6. **SHAP 图正负配色**：贡献 ≥0 红（推高违约）、<0 绿，评委一眼看懂方向。
7. **状态反馈统一**：LLM 调用用 `st.status("正在生成…", expanded=False)`；保存 Key、提取完成等用 `st.toast` 替代 success 占位块。
8. **侧边栏精简**：Key 状态只显示"已配置 ✅ / 未配置 ⚠️"，不回显片段；删掉单选项模型下拉（写死常量）；加"使用说明"expander。
9. **纯手动演示路径**：Tab 1 提供"不上传文件，手动录入指标"开关（data_editor 预置空模板），评委现场 30 秒可跑通全流程。

### 3.4 实施顺序（与现有纪律兼容）

| 阶段 | 内容 | 预估 | 验收 |
|---|---|---|---|
| Phase 1（P0） | 结果 session_state 化 + st.form + fragment | 半天 | AppTest：诊断后切 Tab/提问结果仍在 |
| Phase 2（P1） | st.tabs 重构 + data_editor + 空状态 | 1 天 | AppTest 全绿 + 手动演示路径可走通 |
| Phase 3（P2） | config.toml + CSS + 图表升级 + 侧边栏精简 | 1 天 | 截图对比 + Lighthouse/手工走查 |

> 注意保持项目现有纪律：全部 UI 改动集中在 `app.py` + 新增 `.streamlit/config.toml` + `utils/ui_style.py`，**不触碰** modules/ 与 utils/vector_store.py 的算法逻辑；每阶段跑既有 AppTest 回归（v1.6 已有 AppTest 全绿实践）。

## 五、预期效果

- 首屏从"一屏塞不下的长页面"变为"四标签 + 空状态引导"，演示动线清晰：录入 → 诊断 → 匹配 → 问答。
- 修掉结果消失 bug 与逐键 rerun 后，评委现场操作（切 Tab、追问 RAG）不再翻车，1GB 云端也更稳。
- 视觉统一为金融蓝 + 卡片 + 语义徽章后，"规则卡红黄绿灯"和"双轨四态结论"这两个核心卖点会以最专业的方式呈现。
